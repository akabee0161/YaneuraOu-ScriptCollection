# book_to_ki2.py 仕様書

- 作成日: 2026-09-23
- 前提: `HANDOVER.md`（設計討議の合意内容）。本書はそれを確定仕様に落としたもの。HANDOVER からの変更・追加は「HANDOVERからの差分」に明記する。

## 1. 目的

BookMiner で掘った定跡DB（`.db` / `.ybb`）を、**変化（分岐）付きのKI2棋譜ファイル**に書き出し、人間が将棋所・柿木将棋などの棋譜ビューアで読めるようにする閲覧用ツール。採掘プロセスのQA用途ではない。

## 2. 配置・実行

- スクリプト: `BookMiner/book_to_ki2.py`
- テスト: `BookMiner/tests/test_book_to_ki2.py`（標準 `unittest`。venv に pytest が無いため）
- 実行例（リポジトリルートから）:

```bash
venv/bin/python BookMiner/book_to_ki2.py \
  --book BookMiner/book/backup/peta_book-....db \
  --output BookMiner/book/exported.ki2 \
  [--root "startpos moves 7g7f"] \
  [--max-depth 20]
```

パスはカレントディレクトリ基準でそのまま解決する（特別な基準ディレクトリは持たない）。

## 3. CLI

| 引数 | 必須 | 既定値 | 内容 |
|---|---|---|---|
| `--book` | ○ | — | 定跡DB。`.ybb` は拡張子で自動判別（`read_yaneuraou_book`） |
| `--output` | ○ | — | 出力KI2パス。**cp932** で書き出す（KI2の慣習。`cshogi.KI2.Parser` も cp932 で読む） |
| `--root` | | `startpos` | 展開開始局面。`startpos [moves ...]` / `sfen <sfen> [moves ...]` / 先頭の `position ` 付きも可。`think_sfens.txt` の行をそのまま貼れるよう、最初の `,` 以降（`book_extend_ply=...` 等のメタ情報）は無視する |
| `--max-depth` | | 無制限 | 分岐点（root局面、または prefix 上の分岐した局面）から数えて何手分の定跡手を出力するか（1以上の整数）。prefix の手は数えない |

終了コード: 成功 0、エラー 1（argparse の引数エラーは 2）。エラーは `error: ...` を stderr に出す。

## 4. 入力の読み込みと局面キー

- `BookLib.read_yaneuraou_book(path, ignore_book_ply=True)` を使う。キーは手数を除いた sfen。
- 盤面からのキーは `BookLib.trim_number(board.sfen())`。手数違いの同一局面（手順前後）も同じ局面として引ける。
- 各局面の候補手の順序は **DBのファイル内の並び順をそのまま使う**（`01-terms.md`: 手番側から見て評価値の良い順）。再ソートはしない（peta shock の `value - 1` 等、やねうら王側の並びを尊重するため）。
- `move == "none"` の候補は無視する。非合法手（`move_from_usi` 失敗 / `is_legal` 偽）はスキップし、警告を stderr に出す。

## 5. 棋譜木の構築

1. `--root` を (開始sfen, prefix手順) に分解する。開始sfenが不正なら、または prefix に非合法手があればエラー終了。
2. 開始局面から prefix を指し進める。**prefix の手が本線**になる。prefix 上の局面が DB にあれば、その局面の他の候補（prefix の手以外）を変化として 4. と同じ規則で展開する（`--max-depth` はその分岐点から数える）。
3. prefix 上の局面（開始局面・root を含む）が1つも DB に無ければエラー終了（メッセージで `--root` の指定を促す）。root 自体が DB に無いだけならエラーにしない。
4. root から DFS。各局面で、候補を先頭から順に処理する。先頭候補 = 本線、2番目以降 = その手数の変化。
5. 子局面の展開を止める条件（どれか1つで止め、その指し手自体は出力する）:
   - 子局面が DB に無い（葉）
   - `--max-depth` に到達した
   - **循環**: 子局面が現在の root→現在局面のパス上に既にある → コメントに `循環のため打ち切り` を付ける
   - **合流**: 子局面が既に木の別の場所で展開済み → コメントに `既出局面に合流` を付ける
6. DFS は常に先頭候補から先に深く潜るため、合流局面は「より良い手順側（本線寄り）」で先に展開される。prefix 上の局面は最初から展開済み扱いにし、変化側から到達した場合は `既出局面に合流` とする。

## 6. KI2 出力形式

### ヘッダ

- 開始局面が平手初期局面なら `手合割：平手`。
- それ以外は `cshogi.KIF.board_to_bod(board)`（後手番なら末尾に `後手番` が付く）。手数は 1 から数える。
- 続けて `先手：` `後手：`（空）と空行。

### 指し手

- **1行1手**。表記は `cshogi.KI2.move_to_ki2(move, board)`（`同` は直前手を `board.peek()` で判定するので、実際に push/pop しながら生成する）。
- 各定跡手の直後にコメント行 `*評価値 {v:+d} depth {d}`。
  - `v` は **先手視点**（DBの value は手番側視点なので、後手の手は符号反転）。
  - `d` は DB の depth そのもの（peta_book では葉までの距離、`10-peta-shock.md` 参照）。
  - 循環・合流の注記は同じコメント行の末尾に空白区切りで付ける。
- prefix の手: その局面が DB にあり、手が候補にあればその評価値コメント、候補に無ければ `*定跡候補外`。局面が DB に無ければコメントなし。
- 終局行（`まで N 手で…`）は出さない。

### 変化

- 形式: 空行、`変化：N手`、その変化の手順。N は開始局面から数えた手数（その変化の最初の手の手数）。
- **出力順（重要）**: ある手順を書き終えたら、その手順上の分岐を **手数の大きいものから順に** 書く。同じ手数の複数候補は DB の並び順（2番目、3番目…）。各変化の直後には、その変化自身の分岐を同じ規則で再帰的に書く。
  - 理由: ビューアは `変化：N手` を「直前に書かれた手順を遡って、N手目を持つ手順」に接続する。手数の小さい分岐を先に書くと、後続の分岐が誤った手順にぶら下がる。柿木将棋（Kifu for Windows）の出力順と同じ。

例（本線 A→B→C、2手目の変化 B2、1手目の変化 A2）:

```
手合割：平手
先手：
後手：

▲A
*評価値 +50 depth 2
△B
*...
▲C
*...

変化：2手
△B2
*...

変化：1手
▲A2
*...
```

## 7. 標準出力

成功時に1行サマリ: `wrote {output}: {手数} moves, {展開局面数}/{DB局面数} positions`。

展開局面数 < DB局面数 のときは stderr に `note: {差} positions in the book are not reachable from root (use --root to start from them)` を出す。

- 背景: DBの候補手（MultiPV）に入っていない手で進んだ局面は、root から定跡手だけでは辿れない。実データ `book_miner-20260923093633_77.db` では、対局の11手目 `5g5f` が候補手に無いため、77局面中24局面が平手初期局面から到達不能だった。これらを見るには `--root` に対局の手順（`think_sfens.txt` の行）を指定する（検証時、この指定で 77/77 局面が出力された）。

## 8. スコープ外（YAGNI）

- eval 差による分岐の間引き（DBにある候補は全部出す）
- `.ybb` 専用処理
- KIF / KIF2 など他形式、UTF-8(`.ki2u`)出力

## 9. 既知リスク

- cshogi は KI2 の変化を読み書きできないため、変化構文は自前生成。**実ビューアでの目視確認が必須**（自動テストでは代替できない）。
- 合流判定は「最初に展開した場所」を優先する。先の出現が `--max-depth` で打ち切られていた場合、後の浅い出現も `既出局面に合流` で止まり、その先が見えないことがある（`--max-depth` 無指定なら起きない）。
- 手順の深さは Python の再帰で辿る。`game_ply_limit`（既定200）程度の深さなら再帰上限（1000）に届かない。

## HANDOVERからの差分

1. `parse_position_string` は `BookMiner.py` から import せず、同等の小関数を `book_to_ki2.py` に持つ。`BookMiner.py` は import 時に `json5` を要求し、`enable_print_log()` で `log/` にログファイルを作る副作用があるため。
2. `--root` の `,` 以降を無視する（`think_sfens.txt` の行がメタ情報付きのため）。
3. 循環に加えて **合流（手順前後）打ち切り** を追加。DBが大きくなると同一部分木が指数的に重複出力されるため。
4. 評価値・depth をコメントとして出力する（HANDOVERでは未決）。「読んで研究に取り入れる」目的では評価値が主要情報のため。
5. 到達不能局面数の通知を追加（7章）。「掘れた分は全部見たい」用途なのに、黙って欠落するのを防ぐため。
6. prefix 上の局面の他候補も変化として展開する（5章 2.）。当初案（prefix は一本道）では、対局手順を `--root` に渡しても対局途中の局面の定跡が見えず、実データで 6/77 局面しか出力されなかったため。
